# US-016: Evidence Retrieval Coordinator

## 1. Overview

**User Story ID:** US-016  
**Title:** Evidence Retrieval Coordinator  
**Component:** C-07 - Evidence Retrieval Coordinator  
**Priority:** High  
**Story Points:** 8  
**Assigned To:** Laxmikant  
**Status:** Implemented

This user story coordinates evidence retrieval from enabled evidence source connectors for each identified factual claim. It manages parallel retrieval, timeout handling, bounded retries, and retrieval result generation so that the retrieved evidence can be passed to downstream verification components.

## 2. Objective

The objective is to provide a reliable and efficient mechanism for retrieving evidence for identified claims. The coordinator executes retrieval operations concurrently, handles source failures and timeouts, and produces clear retrieval results indicating whether evidence was successfully obtained or retrieval remains uncertain.

## 3. Input

The evidence retrieval coordinator accepts:

- **claims:** A sequence of identified `Claim` objects generated by US-011.
- **sources:** A sequence of enabled evidence source connectors implementing the `EvidenceSource` interface.

Each claim contains:

- `claim_id`
- `request_id`
- `text`
- `start_offset`
- `end_offset`

Each evidence source implements the `search(query)` method, which accepts a claim as the query and returns a sequence of evidence objects.

## 4. Output

For every identified claim, the coordinator generates a `RetrievalResult` object containing:

| Field | Description |
|---|---|
| `claim_id` | Unique identifier of the claim. |
| `request_id` | Identifier of the request associated with the claim. |
| `claim_text` | Original claim text. |
| `status` | Retrieval status: Success or Uncertain. |
| `evidence` | Collection of retrieved evidence objects. |
| `reason` | Explanation when retrieval is uncertain. |

### Retrieval Status

- **Success:** Evidence was successfully retrieved from at least one enabled source.
- **Uncertain:** No usable evidence was retrieved.

Possible reasons for an Uncertain result:

- `no enabled sources`
- `no evidence`
- `retrieval failure`

## 5. Implementation

The functionality is implemented in:

- `app/retrieval/models.py`
- `app/retrieval/interfaces.py`
- `app/retrieval/coordinator.py`

### Processing Steps

1. Accept identified claims and enabled evidence source connectors.
2. Create retrieval tasks for all claims.
3. Submit each claim's text as a query to the enabled sources.
4. Execute retrieval operations across sources concurrently.
5. Apply a default timeout of 5 seconds to each source attempt.
6. Retry failed or timed-out retrieval requests once.
7. Collect evidence returned by successful sources.
8. Determine the retrieval status for each claim.
9. Return the retrieval results.

### Main Classes and Data Structures

- `Evidence`: Represents an evidence snippet, its source, and its reference.
- `RetrievalStatus`: Defines the retrieval statuses `Success` and `Uncertain`.
- `RetrievalResult`: Represents the retrieval outcome for an individual claim.
- `EvidenceSource`: Protocol defining the common interface for evidence source connectors.
- `EvidenceRetrievalCoordinator`: Coordinates parallel evidence retrieval, timeout handling, retries, and result generation.

### Configuration

| Parameter | Default Value | Description |
|---|---:|---|
| `timeout` | 5 seconds | Maximum wait time per source attempt. |
| `max_retries` | 1 | Number of retries after the initial failed attempt. |

The coordinator validates that the timeout is greater than zero and the retry count is non-negative.

## 6. Integration with Previous User Stories

- **US-011 - Claim IDs and Start/End Offsets:** Provides identified `Claim` objects containing claim IDs, request IDs, claim text, and original-text offsets.
- **US-016 - Evidence Retrieval Coordinator:** Uses the identified claims and enabled evidence source connectors to retrieve evidence for downstream verification.

Enabled-source selection is handled outside the coordinator. Only enabled connectors are passed to it.

The coordinator does not independently determine whether a claim is factually correct. That responsibility belongs to the downstream verification component.

## 8. Expected Outcome

The Evidence Retrieval Coordinator retrieves evidence from enabled sources for identified factual claims while supporting parallel execution, timeout handling, and bounded retries. It produces structured retrieval results with clear statuses and reasons, enabling downstream verification components to process the retrieved evidence.
